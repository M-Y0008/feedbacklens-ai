## 1. 三分钟快速开始

如果你只想马上打开界面，按下面三行做：

```powershell
# 1) 确认本地模型服务在运行（正常情况下装好 Ollama 后会自动常驻）
ollama list

# 2) 进入项目根目录
cd <项目目录>

# 3) 启动界面
python -m streamlit run app/main.py
```

> `<项目目录>` 替换为你本机 clone 或解压后的实际路径；`python` 需为 3.12 且已安装依赖。

浏览器打开：**http://localhost:8501**

首次启动会自动做一次轻量数据库迁移，并在迁移前生成备份 `data\feedbacklens.db.bak`。不会删除或覆盖已有评论与分析数据。

## 2. 环境要求与安装

### 2.1 操作系统与硬件

本机实测环境（可作为最低参考）：

| 项 | 实测值 |
|---|---|
| 操作系统 | Windows 11 家庭版 中文版（64 位） |
| 内存 | 31.4 GB |
| GPU | NVIDIA GeForce RTX 4060 Laptop，8 GB 显存 |
| 磁盘 | 项目与模型合计预留 10 GB 以上（`qwen3:8b` 模型本身约 5.2 GB） |

说明：

- 没有独立显卡也能跑，Ollama 会自动回退到 CPU，但分析会明显变慢。
- 8 GB 显存可以流畅运行默认模型 `qwen3:8b`；同时开游戏或其他占显存的程序可能触发显存不足。

### 2.2 Python

- 版本：**Python 3.12.6**
- 安装位置（本机）：`C:\Program Files\Python312\python.exe`
- 自检命令：

```powershell
python --version
# 应输出：Python 3.12.6
```

如果 `python --version` 指向别的版本，不影响使用，只要用上面的完整路径启动即可。

### 2.3 Python 依赖

项目**没有** `requirements.txt`，依赖已直接安装在上述 Python 环境中。本机实测版本如下（均已被项目实际运行验证）：

| 包 | 已验证版本 | 用途 |

| streamlit | 1.61.1 | 界面框架 |
| pandas | 2.2.2 | 表格与数据校验 |
| plotly | 5.24.1 | 图表 |
| openpyxl | 3.1.5 | 生成 Excel |
| requests | 2.32.3 | 调用本地 Ollama HTTP 接口 |
| altair | 6.2.2 | Streamlit 图表依赖 |
| numpy | 1.26.4 | 数值计算 |
| pyarrow | 16.1.0 | DataFrame 序列化 |

本机无需重复安装。若换到一台新电脑，可按下面命令安装**同一组已验证版本**：

```powershell
  streamlit==1.61.1 pandas==2.2.2 plotly==5.24.1 openpyxl==3.1.5 ^
  requests==2.32.3 altair==6.2.2 numpy==1.26.4 pyarrow==16.1.0
```

检查已安装版本：

```powershell
python -m pip show streamlit pandas plotly openpyxl
```

### 2.4 Ollama 与模型

- Ollama 版本（本机实测）：**0.6.7**
- 服务地址：`http://localhost:11434`
- 项目使用的模型：**`qwen3:8b`**（约 5.2 GB）
- 模型名必须与 `config\analysis.json` 中的 `backends.ollama.model` 完全一致，否则「AI 分析」页会报“未找到配置模型”。

安装与检查：

```powershell
# 查看 Ollama 是否已安装
ollama --version

# 查看本地已有哪些模型
ollama list

# 如果没有 qwen3:8b，拉取（只需一次，约 5.2 GB）
ollama pull qwen3:8b

# 如服务未启动（一般随桌面应用自动启动）
ollama serve
```

拉取完成后再次执行 `ollama list`，应能看到 `qwen3:8b`。

> 本机还装有 `llama3.1:8b`、`mistral-nemo:12b`、`gemma3:27b`、`qwen2.5-coder:7b`，但正式分析口径只用 `qwen3:8b`；其他模型仅作历史试跑参考。

### 2.5 安装完成后的一次性自检

按顺序执行，三项都通过再进入使用：

```powershell
python --version   # Python 3.12.6
ollama list                                            # 能看到 qwen3:8b
Test-Path data\feedbacklens.db                         # True（库已存在）
```

## 4. 首次启动会发生什么

### 4.1 自动建库或轻量迁移

- 如果 `data\feedbacklens.db` **不存在**：自动创建全套表结构（项目、产品、评论、分析、批次、优先级、评估等）。
- 如果库**已存在**但缺少界面阶段新增的结构：执行一次轻量迁移，只做两类事：
  - 新增表：`priority_weights`、`export_logs`、`priority_audit`、`eval_label_audit`（以及既有的 `eval_labels` / `eval_runs` 相关结构）；
  - 新增少量列：如 `priorities.pm_actor`、`eval_runs.prompt_version`、`eval_labels.sample_size`。
- 迁移**不会**修改或删除既有 `feedback`（评论）与 `analyses`（分析结果）数据。

### 4.2 自动备份

- 首次迁移前：用 SQLite 在线备份生成 `data\feedbacklens.db.bak`。
- 之后每次「确认导入」或「回滚批次」前：先把 WAL 落盘，再复制为 `data\feedbacklens.db.bak`；如果 `.bak` 被占用，会改用带时间戳的名字，例如 `feedbacklens.db.20261109211316.bak`，**不会跳过备份**。
- `.bak` 是“写入前快照”，只保留最近一次（时间戳文件会累积）。它不是持续同步的实时副本。

### 4.3 启动命令与访问地址

```powershell
cd <项目目录>
python -m streamlit run app/main.py
```

- 默认地址：**http://localhost:8501**
- 端口与 headless 配置写在 `.streamlit\config.toml`（`port = 8501`、`headless = true`）。
- 终端出现 `You can now view your Streamlit app` 即启动成功；按 `Ctrl+C` 停止。
- 关闭终端窗口会同时停止服务，但不会损坏数据。

### 4.4 可选：在数据库副本上试用

不想动真实库时，可指定另一个数据库文件：

```powershell
$env:FEEDBACKLENS_DB="<副本目录>\feedbacklens.db"
python -m streamlit run app/main.py
```

导出目录也可单独指定：

```powershell
$env:FEEDBACKLENS_EXPORT_DIR="<副本目录>\exports"
```

去掉环境变量的方法是重开一个终端窗口。

## 5. 九个模块逐页说明

左侧边栏的「功能导航」按下面顺序排列；顶部还有「当前项目」选择器。所有页面底部都有一行口径说明：数字来自本地真实数据、AI 解释与事实分开、证据少于 3 条只作弱信号、相关性不等于因果。

### 5.1 项目工作区

**做什么**：创建项目、维护参与对比的产品、查看样本状态和每次分析的历史记录。

**怎么操作**：

1. 展开「新建项目」，填「项目名称」（必填）、「项目描述」。
2. 「参与对比的产品（逗号分隔）」默认是 `ChatGPT_OpenAI, Google_Gemini, Perplexity_AI`，可按需改成你的产品名（中英文逗号都支持）。
3. 点「创建项目」，系统自动把它设为当前项目。
4. 在项目卡片上点「设为当前项目」可切换；右侧会显示样本量、产品数、当前分析版本、需人工复核数。
5. 可修改项目状态（`draft / analyzing / analyzed / archived`），点「保存状态」。
6. 「回收站」可恢复被软删除的项目；「危险操作」区必须先勾选「我确认要移除该项目」才能软删除。软删除**不删除**评论与分析数据。

**会看到什么提示**：

- 没有项目时提示「还没有项目。先在下面创建第一个项目。」
- 项目名称为空提示「项目名称必填。」；产品为空提示「至少选择一个产品。」
- 历史分析表按 `run_id / 模型 / prompt 版本` 留痕；没有记录时显示「该项目还没有分析记录。」

### 5.2 CSV 上传与验证

**做什么**：自动识别字段 → 逐行校验 → 查看数据质量报告 → **确认后**才写入数据库。

**必填字段**（缺任何一个都无法导入）：

| 字段 | 含义 |
|---|---|
| `review_id` | 评论唯一 ID |
| `content` | 评论正文 |
| `score` | 星级 1–5 |
| `app_name` | 应用/产品名 |

建议字段：`at_utc`（评论时间）、`package_name`（包名，可选）。

**怎么操作**：

1. 上传 CSV（UTF-8 或 GB18030 都可以）。
2. 展开「字段映射（已自动识别，可手动修改）」，核对四个必填字段是否映射正确；识别不到时该区域会自动展开。
3. 如果文件里有项目产品列表之外的应用：默认这些行会被拒绝；确认要新增产品时，勾选「允许自动创建项目里不存在的产品」。
4. 查看「质量报告」：总行数、通过校验、被拒绝、重复 `review_id`、重复正文+应用、评分越界、日期无法解析、正文过短、含邮箱/链接、时间范围、拒绝原因。
5. 在「可导入 / 被拒绝」两个页签预览前 20 行；可下载「质量报告 CSV」和「被拒明细 CSV」。
6. 点「确认导入（写入数据库前自动备份）」。
7. 导入完成会显示新增条数、跳过已存在条数、批次 ID 和备份文件名。

**会看到什么提示**：

- 未点确认前：「等待上传 CSV。未点击「确认导入」前不会写入数据库。」
- 缺少必填映射：「缺少必填字段映射：…」
- 有未知应用且未勾选自动创建：「以下应用不在项目产品列表中，相关行已被拒绝：…」
- CSV 解析失败会直接显示异常类型与原因，不会静默失败。
- 「导入批次」区可按批次回滚；已产生分析结果的批次禁止回滚，会提示「该批次已有 N 条分析结果，不能回滚」。回滚前也会自动备份。

### 5.3 AI 分析

**做什么**：调用本地 Ollama，逐条生成结构化结果并落库；同版本已完成的结果自动跳过，可断点续跑。

**怎么操作**：

1. 选择「分析版本（prompt_version）」。默认是全局定稿版 **`v2.2-p2`**。
2. 看顶部标签：后端、模型、`temperature`、`num_ctx`、提示词版本。模型标签为绿色表示匹配成功。
3. 看 KPI：样本量、已完成、降级/跳过、待分析、需人工复核。
4. 选择运行模式：
   - 「续跑待分析」：处理同版本还没有结果的评论；
   - 「重跑 failed / degraded（最多 20 条）」：修复失败或降级结果；
   - 「重跑需人工复核（最多 20 条）」：只重跑被标记需要人工复核的条目。
5. 点「开始分析」，观察进度条与实时计数（会显示 `run_id`）。

**会看到什么提示**：

- 未连上 Ollama：「未连上本地 Ollama（http://localhost:11434）。请先启动 Ollama 服务；已有分析结果仍可正常查看。」
- 连上了但模型名不对：红色错误「Ollama 已连接，但未找到配置模型 qwen3:8b；可用模型：…」。
- 连续 3 条失败会自动停止并提示「连续 3 条失败，已停止本批（避免空转）。请检查 Ollama 服务或模型。」
- 该模式下没有待处理条目：「当前模式下没有需要处理的评论。」
- 中途关掉页面/终端不会丢已完成结果：每条结果单独落库，重新进入后选「续跑待分析」即可。

### 5.4 用户洞察 Dashboard

**做什么**：把 AI 结构化结果汇总成高频问题、主要痛点、功能需求、产品优势；每条都可下钻到 `feedback_id` 与原文。

**怎么操作**：

1. 选择「分析版本」与「产品筛选」（全部产品或单个产品）。
2. 看 KPI：样本量、有效分析（done + degraded）、需人工复核、仅 other（证据不足）及占比。
3. 看各产品样本量与时间窗标签。页面会提示：「各产品样本量与时间窗不同，占比差异不可直接视为优劣；样本不足的条目只作弱信号。」
4. 在四个页签中查看：
   - **高频问题**：主题提及条数（**不含 other 桶**）、主题排行、按主题下钻证据；
   - **主要痛点**：严重度分布（AI 判断，需人工复核）、痛点聚类、证据 ≥3 条的主要洞察，以及「弱信号（证据 <3 条，仅提示，不作结论）」；
   - **功能需求**：Top 10 功能请求与需求明细；
   - **产品优势**：代表性正面原文与正面主题（不含 other）。

**关于「other（证据不足）」**：

- `other` 表示模型无法把这条评论归入 11 个具体主题中的任何一个，或信息不足以判断。
- 它**不等于负面**，也不代表“其他问题”，只是一个“未归类/证据不足”的桶。
- 按规则，`other` 不参与主题排行与占比比较，避免把“没看懂”混进“问题最多”。
- KPI 中会单独显示「仅 other（证据不足）」的条数与占比；这个比例偏高，说明该批数据表达太泛或提示词/模型需要复核，而不是“产品没有问题”。

### 5.5 竞品对比

**做什么**：按产品比较主题、情感与严重度差异，并在页面顶部展示各产品真实样本量与评论时间窗。

**怎么操作**：

1. 选择「分析版本」。
2. 先读「样本覆盖（先读这一行再看差异）」表：产品、样本量、评论时间范围、覆盖天数、仅 other、引文命中率。
3. 看提示条：系统会把各产品时间窗写清楚（本数据集页面实测为 ChatGPT 4 天、Gemini 4 天、Perplexity 30 天），并明确「不能解读为长期趋势、市场份额或产品优劣定论」。
4. 在三个页签中查看：
   - **主题差异**：按各产品自身样本归一化的主题占比（不含 other）、主题 × 产品条数、各产品本窗口内主要主题；
   - **情感与严重度**：情感分布、严重度分布、严重度指标对比（平均严重度、≥4 占比、负面/正面占比）；
   - **证据下钻**：选产品、选主题，查看该产品该主题的全部证据（按严重度与星级排序）。

**会看到什么提示**：

- 时间窗不一致是**必须正视**的限制：短窗口内的比例不能和长窗口直接比“谁更好/更差”。
- 样本量小的产品波动大，任何差异都应回到原文证据再判断。
- 严重度由评论描述判断，不由星级直接推断。

### 5.6 优先级管理

**做什么**：按频率、严重度、核心体验影响、客户影响范围加权（成本为负向），给出 P1/P2/P3 与判断理由；权重和成本可调，人工改判全程留痕。

**怎么操作**：

1. 选择「分析版本」。
2. 调整五个权重（默认 频率 0.30、严重度 0.25、核心体验 0.20、影响范围 0.15、成本 −0.10），点「保存权重并重算」。
3. 看 KPI 与「加权结果总表」：候选问题（仅证据 ≥3 条的主题）、P1（总分 ≥4.0）、P2（2.5–3.99）、P3（<2.5）、人工改判数。
4. 展开任意一条，调整「实施成本」「核心体验影响」「客户影响范围」，填写「修改人」「人工改判最终分级」「判断理由」「PM 备注」，点「保存这一条」。
5. 底部「修改审计」会显示谁在什么时间把哪个字段从什么改成什么。

**会看到什么提示**：

- 权重之和不是 1.00 时提示「当前权重之和为 X（建议为 1.00）。仍会按当前权重计算，但不同条目之间的可比性会下降。」
- 没有足够证据时提示「当前版本没有足够证据（每个主题至少 3 条）形成候选问题。」
- 保存成功会提示原值与新值已写入审计记录；未保存的条目在总表中标注「未保存（按默认参数计算）」。

### 5.7 产品改进方案

**做什么**：把证据充分的痛点转成可执行建议；每条含问题、引文证据、措施、预期改善、优先级、假设与不确定性。

**怎么操作**：

1. 选择「分析版本」。
2. 看 KPI：候选问题、AI 草案（未确认）、PM 已确认、PM 已驳回、尚未生成。
3. 展开某条问题，点「用本地模型生成改进草案」。
4. 草案生成后，可填写「决策人」「决策说明 / 驳回理由」，然后：
   - 「确认采纳」→ 状态变为「PM 已确认」；
   - 「标记待验证」→ 仍属 AI 草案；
   - 「驳回」→ 记录驳回理由；
   - 「重新生成」→ 覆盖当前草案并重置确认状态。

**会看到什么提示**：

- AI 草案与 PM 决策在界面与数据层严格分开：草案标「AI 草案 · 未确认」，已确认标「PM 已确认」。
- 未连上模型时提示「未连上本地 Ollama…可以查看已有方案与做人工确认，但暂不能生成新草案。」
- 生成失败会显示具体错误，不会把失败伪装成成功。
- 页面明确：AI 草案不会被当成已确认决策；AI 估计的改善效果未经验证。

### 5.8 报告导出

**做什么**：导出 Excel（必做，固定九张表）与可打印 HTML（PDF 的免费替代）。

**Excel 九张表**：

1. 项目概述
2. 数据来源与样本覆盖
3. 数据质量
4. 核心洞察
5. 痛点
6. 竞品对比
7. 优先级
8. 改进建议
9. 局限说明

**怎么操作（Excel）**：

1. 选择「导出分析版本」。
2. 点「生成 Excel 并保存到本地」，成功后显示文件名与本地路径。
3. 点「下载 Excel 报告」。

**怎么操作（PDF）**：

本项目**不支持直接导出 PDF**，也不会用付费库伪装支持。正确做法：

1. 点「生成可打印 HTML（PDF 替代）」；
2. 点「下载可打印 HTML」；
3. 用浏览器打开该 HTML；
4. 按 `Ctrl+P`，打印目标选择「另存为 PDF」。

**会看到什么提示**：

- 没有项目：「请先在「项目工作区」创建或选择项目。」
- 没有分析结果：「该项目还没有分析结果，请先到「AI 分析」页运行。」
- PDF 区域会明确写：「当前没有启用直接导出 PDF…替代方案：生成自包含的可打印 HTML，浏览器打印 → 另存为 PDF。」
- 「导出记录」表来自 `export_logs`，没有记录时提示「还没有导出记录。生成一次后会写入 export_logs 表。」

### 5.9 AI 质量评估

**做什么**：人工标注 → 与 AI 结果逐字段比对 → 准确率与错误分布；标注只来自你本人的输入，系统不预填。

**怎么操作**：

1. 选择「对比分析版本」。
2. 选择「标注样本量」：每产品 10 条（共 30）或每产品 20 条（共 60，正式标注，默认）。
3. 填写「标注人」（默认 `PM`）。
4. 在「人工标注」页签选一条待标评论：
   - 先读原文；
   - AI 结果默认折叠在「查看 AI 结果（参考，可能影响你的判断）」里，建议先自己判断再展开；
   - 选择主题（可多选）、情感、意图、严重度，可填备注；
   - 点「保存并下一条」。
5. 已标注条目可在「修改已标注条目」中回改；保存会覆盖并留痕。
6. 在「AI vs 人工」页签查看：已标注数、主题命中率、主题完全一致、情感准确率、意图准确率、严重度±1、四字段全对、引文命中率、情感混淆矩阵、按产品/按主题的错误分布。
7. 点「保存本次评估记录」，会写入一条 `eval-` 开头的记录，包含模型与提示词版本。
8. 在「版本与历史」页签查看历史评估记录与标注修改痕迹。

**会看到什么提示**：

- 四个字段没选全就保存：「请先自行选择主题、情感、意图与严重度，系统不会替你填写。」
- 修改已标注条目会提示「已覆盖 #… 的标注，原值与新值已写入修改记录。」
- 当前样本量下没有标注时：「当前样本量设置下还没有已标注条目，先切回「标注未标条目」。」
- 如果之前标过另一套样本量，会提示「另有 N 条标注属于其他样本量设置，不计入当前 60/30 条统计。」
- 错误率下方固定提示：「错误率基于当前已标注样本，样本量小时波动大，不能作为最终结论。」

## 6. 完整分析路径（从新建项目到导出报告）

以下步骤可直接照抄执行。假设你要从零跑完一次完整分析。

**第 1 步：启动 Ollama**

```powershell
ollama list
```

确认能看到 `qwen3:8b`。没有就先 `ollama pull qwen3:8b`。

**第 2 步：启动界面**

```powershell
cd <项目目录>
python -m streamlit run app/main.py
```

浏览器打开 http://localhost:8501。

**第 3 步：新建项目**

进入「项目工作区」→ 展开「新建项目」→ 填项目名称 → 填参与对比的产品（逗号分隔）→ 点「创建项目」。

**第 4 步：上传评论**

进入「CSV 上传与验证」→ 上传 CSV → 核对「字段映射」中的 `review_id / content / score / app_name` → 查看质量报告与被拒明细。

**第 5 步：确认导入**

确认「可导入」条数合理后，点「确认导入（写入数据库前自动备份）」。记下批次 ID。

**第 6 步：运行 AI 分析**

进入「AI 分析」→ 确认版本为 `v2.2-p2`、模型标签为绿色 `qwen3:8b` → 选择「续跑待分析」→ 点「开始分析」→ 等待进度条完成。

**第 7 步：检查分析结果**

看 KPI：「待分析」应为 0；「降级/跳过」与「需人工复核」如果较多，先看状态分布，必要时用「重跑 failed / degraded（最多 20 条）」修复。

**第 8 步：看洞察**

进入「用户洞察 Dashboard」→ 依次看「高频问题 / 主要痛点 / 功能需求 / 产品优势」→ 对关键主题展开证据，核对原文与 `feedback_id`。

**第 9 步：看竞品差异**

进入「竞品对比」→ 先读「样本覆盖」与时间窗提示 → 再看主题、情感、严重度 → 用「证据下钻」核对差异是否真实。

**第 10 步：定优先级**

进入「优先级管理」→ 必要时调整权重并「保存权重并重算」→ 对关键条目调整成本/体验影响/范围 → 需要改判时填写修改人、最终分级、判断理由 → 「保存这一条」。

**第 11 步：生成改进方案并确认**

进入「产品改进方案」→ 展开问题 → 「用本地模型生成改进草案」→ 人工复核后选择「确认采纳 / 标记待验证 / 驳回」，填写决策人与理由。

**第 12 步：导出**

进入「报告导出」→ 选版本 → 「生成 Excel 并保存到本地」→ 「下载 Excel 报告」。

需要 PDF 时：点「生成可打印 HTML（PDF 替代）」→ 下载 → 浏览器打开 → `Ctrl+P` → 另存为 PDF。

**第 13 步（可选）：做质量评估**

进入「AI 质量评估」→ 标注样本量选 60 → 逐条人工标注 → 在「AI vs 人工」查看指标 → 「保存本次评估记录」。

## 7. 数据与隐私

### 7.1 数据存在哪

| 内容 | 位置 | 说明 |
|---|---|---|
| 主数据库 | `data\feedbacklens.db` | SQLite；运行时还有 `-wal` / `-shm` 临时文件 |
| 写前备份 | `data\feedbacklens.db.bak` | 最近一次写前快照 |
| 历史备份 | `data\feedbacklens.db.<时间戳>.bak` | 备份冲突时自动改用时间戳名 |
| 上传的原始 CSV | `data\uploads\` | 保留上传文件副本，便于追溯 |
| 导出文件 | `data\exports\` | Excel 与可打印 HTML；首次导出时自动创建 |
| 示例数据 | `data\samples\sample_450.csv` | 450 条示例评论 |
| 原始数据 | `data\raw\` | 原始 CSV/ZIP |
| 阶段报告 | `reports\` | 评估、对比、质量审计等 Markdown |

所有数据都在本机，不上传到任何云端，不使用付费 API，不绑定支付方式。

### 7.2 原始评论在哪张表

原始评论保存在 `feedback` 表，主要字段：

`id`、`project_id`、`batch_id`、`review_id`、`product_id`、`content`（原文）、`score`（星级）、`review_at`（UTC ISO 8601）、`lang`、`source`、`meta_json`、`content_hash`、`created_at`。

AI 结果单独保存在 `analyses` 表（主题、情感、意图、痛点、功能请求、严重度、引文、置信度、`needs_human_review`、`status`、`raw_output`、`error`、`run_id`、`model_name`、`model_version`、`prompt_version` 等）。原文永不被 AI 结果覆盖。

### 7.3 哪些字段不入库

- **`user_name` 与 `user_image` 在入库前直接丢弃**，数据库中没有这两列，界面也不展示。
- `meta_json` 只保留：`thumbs_up_count`、`review_created_version`、`app_version`、`scrape_lang`、`scrape_country`、`scraped_at_utc`。
- 追溯个人评论只用 `review_id` 与 `feedback_id`。

### 7.4 如何备份

**日常自动备份**：确认导入、回滚批次、首次迁移前都会自动生成 `.bak`。

**手动完整备份**（推荐每周一次，或做重大操作前）：

1. 先停止 Streamlit（终端 `Ctrl+C`）。
2. 复制整个 `data` 目录到外部硬盘或另一个本地目录：

```powershell
Copy-Item -Recurse "<项目目录>\data" `
  "D:\FeedbackLensBackup\data_20261109"
```

停止服务后复制，可避免 `-wal` / `-shm` 未落盘导致的不一致。

### 7.5 如何恢复

1. 停止 Streamlit（`Ctrl+C`），确保没有进程占用数据库。
2. 把当前库改名留底：

```powershell
cd <项目目录>\data
Rename-Item feedbacklens.db feedbacklens.db.broken
```

3. 删除当前的 `feedbacklens.db-wal` 与 `feedbacklens.db-shm`（它们属于旧库；若不确定，先移到别处而不是直接删）。
4. 把要恢复的备份复制为 `feedbacklens.db`：

```powershell
Copy-Item feedbacklens.db.bak feedbacklens.db
```

5. 重新启动界面。系统会检测结构并按需做轻量迁移。

注意：`.bak` 是**最近一次写入前**的状态。恢复后，自那次写入之后的新数据会丢失，因此恢复前务必先按 7.4 留一份当前库。

## 8. 常见问题排查

### 8.1 端口 8501 被占用

现象：启动时报 `Address already in use` 或浏览器打不开。

处理：

```powershell
# 查看谁占用 8501
netstat -ano | findstr :8501

# 结束对应进程（把 <PID> 换成上面查到的数字）
taskkill /PID <PID> /F
```

或直接换端口启动：

```powershell
python -m streamlit run app/main.py --server.port 8511
```

然后打开 http://localhost:8511。

### 8.2 模型未就绪或名称不匹配

现象 A：「未连上本地 Ollama（http://localhost:11434）」。

处理：

```powershell
ollama list          # 若无响应，说明服务没起
ollama serve         # 启动服务；保持该窗口运行
```

现象 B：红色错误「Ollama 已连接，但未找到配置模型 qwen3:8b；可用模型：…」。

原因：`config\analysis.json` 里的 `backends.ollama.model` 与本地模型名不一致。

处理二选一：

```powershell
# 方案 1：拉取配置里要求的模型
ollama pull qwen3:8b
```

```jsonc
// 方案 2：改 config\analysis.json，把 model 改成 ollama list 中已有的名字
"model": "qwen3:8b"
```

改完配置后需要重启 Streamlit（`Ctrl+C` 再启动）才会生效。

### 8.3 显存不足或温度过高

- 默认模型 `qwen3:8b` 约 5.2 GB，8 GB 显存可运行；同时开游戏、浏览器大量视频或其他 AI 程序可能挤爆显存。
- 界面本身是**逐条串行**分析，不会并发压满显存。
- 如出现 `CUDA out of memory` 或 Ollama 报显存错误：关闭占显存的程序，必要时重启 Ollama（退出桌面应用后重新打开）。
- 温度监控（另开一个终端）：

```powershell
nvidia-smi
```

- 本次 60 条实跑时 GPU 温度约 45–72°C。若持续超过 90°C，应停止分析、等待降温，并检查散热。
- 显存不足时 Ollama 可能自动回退 CPU，分析仍能完成，但每条耗时明显增加；不要误以为程序卡死。

### 8.4 上传字段识别失败

现象：字段映射空白，或提示「缺少必填字段映射」。

处理：

1. 打开「字段映射（已自动识别，可手动修改）」逐个下拉选择。
2. 确保四个必填字段都映射：`review_id`、`content`、`score`、`app_name`。
3. 检查 CSV 表头是否有空格、换行或合并单元格；必要时先用 Excel 另存为「CSV UTF-8」。
4. `score` 必须是 1–5 的数字；`at_utc` 建议用 ISO 格式（如 `2026-11-01T12:00:00Z`）。
5. 应用名与项目产品不一致时，相关行会被拒；确认要新增产品就勾选「允许自动创建项目里不存在的产品」。
6. 被拒原因可在「质量报告」和「被拒明细 CSV」中逐条查看。

### 8.5 分析中断后如何续跑

- 每条结果单独落库，中断不会丢已完成的部分。
- 重新进入「AI 分析」，选择同一「分析版本」，运行模式选「续跑待分析」，点「开始分析」。
- 已 `done` 的条目会自动跳过；失败或降级的条目用「重跑 failed / degraded（最多 20 条）」。
- 需要人工复核的条目用「重跑需人工复核（最多 20 条）」。
- 不要为了“重来”删除数据库；重跑同版本会按幂等键更新结果并留痕。

### 8.6 导出文件找不到

- 导出文件统一在 `data\exports\`，文件名形如 `FeedbackLens_p<项目ID>_<版本>_<时间戳>.xlsx`。
- 页面「导出记录」表来自 `export_logs`，可直接看到路径与行数。
- 如果只点了「下载」而没点「生成」，不会有新文件；需先生成再下载。
- 浏览器下载的文件通常在「下载」文件夹，以页面显示的文件名为准。
- PDF 不会直接生成；请下载 HTML 后用浏览器 `Ctrl+P` 另存为 PDF。

### 8.7 其他常见现象

| 现象 | 处理 |
|---|---|
| 启动报「数据库无法以 WAL 打开」 | 关闭占用数据库的进程（另一个 Streamlit、SQLite 工具），确认 `data` 目录可写后重试 |
| 页面空白或一直转圈 | 看终端是否报错；`Ctrl+C` 重启；确认 8501 没有被旧进程占用 |
| 图表不显示 | 确认浏览器未拦截本地脚本；换 Edge/Chrome 再试 |
| 分析很慢 | 正常现象：本地 8B 模型逐条推理；本次 60 条累计约 144.6 秒，长评论会更慢 |
| 想在不影响真实库的情况下试操作 | 用第 4.4 节的 `FEEDBACKLENS_DB` 指向副本 |

## 9. 已知限制

1. **单机单人**：没有账号体系、权限控制与多人协作；同一时间只建议一个人使用，数据库是本地 SQLite。
2. **未做移动端**：界面为桌面浏览器布局，手机小屏未适配。
3. **小样本评估不能外推**：正式评估只有 **60 条**人工标注（每产品 20 条）。在该样本上的指标为：主题命中 76.7%、主题完全一致 71.7%、情感 81.7%、意图 85.0%、严重度±1 86.7%、四字段全对 46.7%、引文命中 100%。这些数字只描述这 60 条，**不能推广为“模型整体准确率”**；样本量小，波动大。
4. **提示词版本**：当前定稿与生产口径是 **`v2.2-p2`**。`v2.3` 是一次**已记录但未采用**的实验：只改了四条通用口径，在同样 60 条上四字段全对仍为 46.7%（改好 3 条、改坏 3 条），严重度±1 反而从 86.7% 降到 81.7%，因此**不推广**，全局配置仍为 `v2.2-p2`。
   - 注意：页面版本下拉框中可能看到 `v2.3`，那是 60 条实验数据（`run_id` 为 `v23-60-20261109-204825`），仅供对比查看，不要当作正式分析口径。
5. **PDF 不直接支持**：只能生成可打印 HTML，再用浏览器“打印 → 另存为 PDF”；这是零付费约束下的替代方案。
6. **数据窗口与抽样有限**：评论来自特定地区、英文、特定时间窗与抽样方式；竞品之间时间窗差异很大（页面实测 ChatGPT 4 天、Gemini 4 天、Perplexity 30 天），**不能解读为长期趋势、市场份额或产品优劣定论**。
7. **AI 输出必须人工复核**：`needs_human_review = true` 的结果、证据少于 3 条的“弱信号”、仅 `other` 的评论，都不能直接作为结论；AI 解释与事实在界面中分开标识，相关性不等于因果。
8. **主题与严重度是模型判断**：严重度不由星级直接推断；短文本、反讽、混合情绪容易判错，必要时用「AI 质量评估」页持续校准。
9. **报告结构固定**：Excel 固定九张工作表；暂不支持自定义模板、图表嵌入或定时自动导出。
10. **单人维护的本地工具**：没有云端同步、远程访问与自动升级；迁移电脑需手动复制目录并重装依赖。
